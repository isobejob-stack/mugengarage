# ADR-002: 整備実績ドメインをブログへ統合する

- **状態**: 採用（2026-08-17）
- **決定者**: 発注者（エムガレージ）
- **影響範囲**: FR-MNT-001〜003、SCR-PUB-013/014、SCR-ADM-017/018、`maintenance_records` テーブル

## 背景

初期の要件定義では「整備実績」を独立したコンテンツ種別として設計した
（`docs/requirements/02_functional_requirements.md` 12章）。専門店としての技術力を
示す資産であり、ブログとは別に一覧・詳細ページと管理画面を持たせていた。

運用を始めてみて、次の2点が明らかになった。

1. **書く側から見て、記事と整備実績を書き分ける必然性が薄い**。
   どちらも「店主が書く読み物」であり、書き分けの基準を運用者が判断できない。
2. **読む側から見ても、入口が分かれている必要が無い**。
   実データは整備実績1件に対しブログ7件で、独立した導線を維持する量ではなかった。

同時に、発注者から「サイト全体として情報量が多く、UIとしての負荷がかかっている」という
指摘があり、第一階層のナビゲーションを減らす方針が決まった。

## 決定

整備実績を独立したドメインとして持つのをやめ、**ブログ（`articles`）のカテゴリの1つ**として扱う。

- ブログのカテゴリを5分類に固定する
  （新着入庫／購入ガイド／整備記録／技術解説／トリビア・豆知識。定義は `lib/content/categories.ts`）
- 既存の整備実績は `articles` へ移行し、`category = '整備記録'` とする
- `/maintenance-records` および `/maintenance-records/:slug` は `/blog` へ308リダイレクトする
- 管理画面・API・型定義から整備実績ドメインを撤去する

## 廃止・読み替えになる要件ID

| 旧ID                     | 扱い                                                             |
| ------------------------ | ---------------------------------------------------------------- |
| FR-MNT-001（登録・編集） | FR-BLOG-001 に統合。カテゴリ「整備記録」の記事として作成する     |
| FR-MNT-002（関連付け）   | FR-BLOG-002 に統合。記事の関連コンテンツ機能をそのまま使う       |
| FR-MNT-003（公開ページ） | FR-BLOG-003 に統合。`/blog?category=整備記録` で絞り込める       |
| SCR-PUB-013/014          | 廃止。SCR-PUB-006/007（ブログ一覧・詳細）が役割を引き継ぐ        |
| SCR-ADM-017/018          | 廃止。SCR-ADM-010（ブログ記事編集）が役割を引き継ぐ              |

## データの扱い

移行は手実行のSQL（`supabase/migrations/20260817010000_merge_maintenance_records_into_articles.sql`）
で行い、2026-08-17に本番へ適用済み。

- `maintenance_records` の行は**物理削除していない**（BR-DEL-001）。`deleted_at` を立てただけで、
  本文は残っている。移行結果に問題が見つかったときに突き合わせられる状態を保つため
- `related_contents` の `maintenance_record` 参照は、移行先の記事へ張り替えた
- テーブル自体も残している。参照するコードは無いが、
  次のスキーマ変更のタイミングまで安全側に倒して残す

## 結果として残った意図的な「消し残し」

コードから完全に消していない箇所が1つある。

- `lib/seo/paths.ts` の `case "maintenance_record"`
  → `seo_metas` に古い型の行が残りうるため分岐は残し、行き先だけ `/blog` に向けている

## 代替案

- **案A: 整備実績を残したまま、ブログ一覧に混ぜて表示する**
  入口は1つになるが、書く側が2つの管理画面を使い分ける問題は残る。却下。
- **案B: タグ（`tags` / `taggings`）で分類する**
  `articles.category` が既にあり、`tags` は0件で未使用だった。
  1記事1分類で足りる要件に対してjoinが増えるだけのため却下。
