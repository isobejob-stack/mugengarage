# 在庫車両の入れ替え（2026-11-07）

## 依頼内容

> 重複は避けつつ、このサイトの中にある在庫車両を一括で既存のサイトに入れたい。
> 写真は後で入れるから、まずはいまサイトページ内に入ってるものを全て消して、
> 以下2つのURL内の在庫情報を入れてもらえる？
>
> - https://www.kurumaerabi.com/shop/detail/14921/car/
> - https://www.goo-net.com/usedcar_shop/9570660/stock.html

## 結論

- **車選びドットコムの掲載中20台**を、入れ替え用SQL
  [`supabase/replace-inventory-2026-11-07.sql`](../../supabase/replace-inventory-2026-11-07.sql)
  にまとめた。SupabaseのSQL Editorで1回実行すれば反映される（手順はファイル冒頭）
- **グーネットは読み取れなかった**。グーネット側がこの作業環境からの接続を拒否しており、
  サイト側のアクセス制限を回避するやり方は取らなかった。
  8月に共有されたグーネットの掲載15台と突き合わせた結果は下の「グーネットとの重複」を参照
- 写真は入れていない（依頼どおり、あとで管理画面から追加する）

## SQLがやること

1. いま登録されている車両を**サイトからすべて消す**
   - 管理画面の「削除」と同じ論理削除（BR-DEL-001/002）。
     管理画面 > 車両 > 「削除済みを見る」から元に戻せる
   - **売約済**の車両は消さない（BR-DEL-003。オーナーズアーカイブとして残すルール）
   - 下書き・商談中なども含めて消す（「全て消して」のため）
2. 車選びドットコム掲載中の20台を登録し、公開状態にする
3. 消した記録・登録した記録を監査ログに残す（操作者は「システム」）

### 重複を避ける仕組み

- 各車両のIDを車選びドットコムの掲載ID（`14921-135` など）から作っているため、
  **何回実行しても同じ車が二重に登録されることはない**
- 2回目以降は「1. いまの在庫を消す」を行わない。
  1回目のあとに管理画面で追加した車両を消してしまわないため
- メーカー・車種は、同じURL名か同じ名前のものが既にあればそれを使い、新しく作らない
  （管理画面の「その他（手入力）」で作った車種はURL名が違うことがあるため、名前でも探す）
- エラーが出た場合は途中までの変更もすべて取り消される（1つのトランザクション）

### 検証

本番と同じマイグレーション一式と `supabase/setup.sql` を当てたローカルのPostgreSQL 16で、
次の状態を作ってから実行して確認した。

- 公開中の車両12台＋管理画面で追加した車両1台、下書き1台、売約済1台、削除済み1台
- 手入力で作られた「メルセデス・ベンツ」「Eクラス」（URL名が `mb` / `e`）

結果: 公開中・下書きの14台が削除され、売約済・削除済みは変化なし。20台が登録され、
全車にURLあり。メルセデス・Eクラスは既存のものが使われ二重に作られなかった。
2回目の実行では登録・削除・監査ログとも増えなかった。
メルセデスのマスタが無い状態からの実行でも、メーカー・車種が作られて正しく登録された。

## 割り切ったこと

- **一覧カードの車名にグレードは出ない**。カードの車名は「メーカー＋車種＋グレード」で、
  グレードは「車種 → シリーズ → 世代 → グレード」の階層マスタ（図鑑と共用）に紐づく。
  この階層を作るには年式・型式から世代（XJ40・X300・X308・X350 等）を判定する必要があり、
  掲載情報だけでは確定できないため今回は作らなかった。
  代わりに、詳細ページの販売コメント先頭とページタイトル（SEO）にグレード名を入れた。
  カードで「ジャガー XJ」が11台並ぶ状態は従来と同じ
- 車台番号は掲載が下3桁のみのため入れていない（車台番号欄は一意制約があり、部分値は入れられない）
- 車両所在地は入れていない。掲載の所在地は事務所の住所で、販売コメントには
  「事務所とは別の場所に車両を保管」とあるため
