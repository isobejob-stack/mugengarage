# ISSUE-004: 論理削除の復元UI未整備・自動テスト未整備

## 背景
2026-08-06、FR-INV-003ほか6FRにまたがる論理削除（`deleted_at`セット）機能を実装した。engineering-directorレビューにより以下2点が中程度の課題として指摘され、当該PRのブロッカーにはしないが記録すべきとされた。

## 課題1: BR-DEL-002「管理画面上では復元可能」の自己サービス的な復元手段が存在しない
- `docs/development/testing_strategy.md` 5章のリリース前チェックリストに「論理削除したデータが管理画面上では復元可能であること」と明記されているが、`docs/api/rest_api.md`・`docs/screens/`のいずれにも復元用エンドポイント・画面が定義されていない
- 現状、DBレベルでは`deleted_at`をnullに戻せば復元可能だが、非エンジニア運用者が自分でUndoできる手段はゼロ
- 対応方針は事業責任者エージェントと協議の上、以下いずれかを決定する
  - (a) 各ドメインの管理画面に「削除済み一覧」＋「復元」ボタンを追加する
  - (b) MVPでは開発者による直接DB復旧のみとし、BR-DEL-002にその旨を注記する

## 課題2: BR-DEL-003等の最優先業務ルールに対する自動テストが存在しない
- リポジトリ全体にテストランナー（Vitest/Jest等）が未導入、テストファイルが1つもない
- 「売約済み車両は削除不可（409）」という重要な分岐を含め、BR-DEL-001〜003・BR-HIST-001等の最優先ルールを担保する自動テストがない
- 対応方針：テスト基盤導入をADR化し、まず最優先業務ルールから自動テストを整備することを推奨
