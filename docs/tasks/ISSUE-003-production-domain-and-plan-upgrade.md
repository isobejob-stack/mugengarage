# ISSUE-003: 本番公開前にVercel Proプラン移行＋独自ドメイン設定が必要

## 起票日

2026-08-05

## 内容

現在、本プロジェクトはVercelのHobby（無料）プランで`https://mugengarage.vercel.app`として動作している。Vercel公式ドキュメント（[Hobby Plan](https://vercel.com/docs/plans/hobby), 2026-06-16更新版）に以下の明記がある。

> As stated in the fair use guidelines, the Hobby plan restricts users to non-commercial, personal use only.

エムガレージは実店舗の商用サイトであり、Hobbyプランでの本番運用はVercelの利用規約（fair use guidelines）に反する。

## やるべきこと（本番公開までに）

1. **Vercel Proプランへのアップグレード**
   - Vercelダッシュボード > Settings > Billing から実施（発注者/isobejob本人のクレジットカード登録・支払いが必要なため、Claude Codeは代行不可）
   - 14日間の無料トライアルあり
2. **独自ドメインの取得・設定**
   - ドメイン名：`m-garage.com`（2026-08-05時点で決定、まだ未取得）
   - 購入先：Vercel経由での購入を予定（DNS設定が自動で行われるため）
   - 取得後、Vercel Settings > Domains に追加すればDNS設定は自動化される（deployment.md 8章）
   - ドメイン購入は決済を伴うため、Claude Codeは代行不可（本人の操作が必要）

## 注意点

- **独自ドメインを設定するだけではプラン規約違反は解消しない**。Proプランへのアップグレードとドメイン設定はセットで必要
- 開発・Preview環境での`*.vercel.app`利用は許容範囲内（Hobbyプランの想定用途）

## 追記（2026-08-08）: Hobbyプランの制約が実際にデプロイを止めていた

規約上の問題だけでなく、**Hobbyプランの機能制限が実害として発生した**。

`vercel.json` の公開予約バッチを毎時（`0 * * * *`）で登録していたところ、
Vercelが `Hobby accounts are limited to daily cron jobs.` を理由に**デプロイを丸ごと拒否**し、
`d8e122d` 以降の全コミットが本番に反映されない状態になっていた。

暫定対応として実行間隔を1日1回（`0 0 * * *`）に落としてデプロイを復旧させたため、
**現在は公開予約の反映が最大約1日遅れる**。
Proプランへのアップグレード完了後、`vercel.json` のscheduleを `0 * * * *` に戻すこと。

## 追記（2026-11-16）: 「エムガレージ」で検索しても出ない件と、移行の順番

### 発注者の質問

> mugengarage で調べたらめっちゃ出てくるけど、エムガレージで調べると出てこないな。ドメイン取り直した方がいい？

### 原因（ドメイン名ではない）

- 「mugengarage」はこのサイトしか使っていない文字列なので、それで探せばこのサイトしか当たらない（＝出て当然）
- 「エムガレージ」は似た名前の店が多く、同じ店の**車選びドットコム・グーネットの掲載ページが既に上位を取っている**
- Googleがこのサイトを知ったのは Search Console 登録（2026-11-11）からで、まだ数日。トップのタイトルを
  「エムガレージ｜ジャガー・ディムラー専門店｜…」に変えたのも同じ日で、Googleが読み直すまで時間がかかる
- 「このサイトがエムガレージの公式サイトだ」と外から示すもの（Googleビジネスプロフィール、掲載媒体の
  「ホームページ」欄、Instagramのプロフィールのリンク）がまだ1つも無い。**順位を決めているのはここ**
- サイトの中身（タイトル・見出し・構造化データの店名と別名）は既に「エムガレージ」になっている（SEO_AIO_2026-11-11.md）

ドメイン名に「m-garage」が入っても、それだけで「エムガレージ」の順位が上がることはほとんど無い。

### それでも独自ドメインは「今」取るのがよい

1. **これから外部のリンクを張るから**。Googleビジネスプロフィール・掲載媒体・Instagram に旧URLで登録すると、
   移行のときに全部張り替えることになり、その間に積み上がった評価も引っ越しになる。
   旧URLの評価はまだほぼゼロなので、**引っ越しの損が一番小さいのは今**
2. 「mugengarage」は「ムゲンガレージ」と読め、店名「エムガレージ」と合っていない。検索結果やLINEでURLを見た人が同じ店だと分かりにくい
3. もともと本番公開に必須（このISSUEの本題：Hobbyプランは商用利用不可）

### ドメイン名

- `m-garage.com`（2026-08-05に決定）が**まだ空いているかは未確認**（作業環境から確認できなかった）。購入画面で確認する
- 空いていなければ `m-garage.jp`（日本の店として信頼されやすい。日本国内の住所があれば取れる）など、**店名どおり「m-garage」を含む名前**にする
- 「jaguar」を含む名前は避ける（Jaguar Land Rover の商標のため）

### コード側の準備（2026-11-16 実装済み）

`NEXT_PUBLIC_SITE_URL` を新しいドメインに変えて再デプロイすると、次がすべて切り替わる。

- 正規URL・サイトマップ・robots.txt・構造化データ・llms.txt・IndexNow の送信先（`lib/site-config.ts` の `SITE_URL`）
- **旧URL（mugengarage.vercel.app）へのアクセスを、同じパスのまま新しいドメインへ恒久転送（308）**
  （`lib/seo/legacy-host.ts`、`next.config.ts`）。検索エンジンはこれを見て旧URLの評価を新しいドメインへ引き継ぐ。
  `/api`（定期処理が転送で止まるため）と Search Console の確認ファイルは転送しない。プレビューのURLも転送しない

### 移行の手順（発注者の操作）

順番が大事。**新しいドメインでサイトが開けるようになる前に環境変数を変えると、旧URLが開けないドメインへ転送されてサイトに誰も入れなくなる。**

1. Vercel を Pro プランにする（このISSUEの本題）
2. Vercel > プロジェクト > Settings > Domains でドメインを購入・追加し、**新しいドメインでサイトが開けることを確認**
3. Vercel > Settings > Environment Variables で `NEXT_PUBLIC_SITE_URL` を `https://（新しいドメイン）` にする（Production）→ **Redeploy**
   （`NEXT_PUBLIC_` で始まる値はビルドのときに埋め込まれるため、再デプロイしないと切り替わらない）
4. 旧URLを開いて新しいドメインに転送されることを確認（例：`https://mugengarage.vercel.app/vehicles` → `https://（新しいドメイン）/vehicles`）
5. Supabase > Authentication > URL Configuration：`Site URL` を新しいドメインに、`Redirect URLs` に `https://（新しいドメイン）/api/auth/callback` を追加
   （やらないと、管理画面のパスワード再設定メールのリンクが旧URLに飛ぶ）
6. Search Console に新しいドメインを登録（「ドメイン」を選び、DNSのTXTレコードで確認するのが確実）→ サイトマップ `sitemap.xml` を送信 →
   旧URLのプロパティの「設定 > アドレス変更」で新しいドメインへの移転を届け出る（旧URLのプロパティは消さない）
7. Bing Webmaster Tools にも新しいドメインを追加（Search Console からインポート）
8. ここまで終わってから、Googleビジネスプロフィール・車選びドットコム・グーネット・Instagram に**新しいドメインのURL**を登録する
   （SEO_AIO_2026-11-11.md「店側でやること」1〜3）
9. 旧URL（mugengarage.vercel.app）は消さない。転送が評価の引き継ぎそのものなので、残し続ける
