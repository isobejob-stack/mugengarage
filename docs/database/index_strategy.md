# index_strategy.md — インデックス戦略

## 1. Purpose（目的）

table_definitions.md で定義したテーブルに対し、どのカラムにインデックス（検索を高速化する仕組み）を張るかを定義する。03_non_functional_requirements.md 4章（パフォーマンス要件）「検索・絞り込みは体感的な待ち時間を感じさせない応答速度」を満たすことを目的とする。

## 2. Scope（対象範囲）

想定規模（03_non_functional_requirements.md 3章：在庫10〜50台、アーカイブ含め将来数百台）を前提に、過剰な最適化は行わず、実際に検索・絞り込み・一覧表示で使われるカラムに絞ってインデックスを設計する。

## 3. 基本方針

- 主キー（id）・外部キーには自動的にインデックスが作られる（PostgreSQLの標準動作、外部キーは明示的にINDEX化する）
- `slug` や `email` 等のUNIQUE制約カラムは自動的にインデックスが作られる
- 本プロジェクトの規模（在庫10〜50台）では、複雑な複合インデックス・パーティショニングは不要と判断する（過剰最適化の回避、00_project.md 12章）
- 論理削除（`deleted_at`）を持つテーブルは、「未削除のみ」を効率よく検索できるよう部分インデックス（Partial Index）を検討する

## 4. テーブル別インデックス方針

### 4.1 vehicles（在庫検索の中核）

検索仕様（FR-SRCH-001）で絞り込み条件になっているカラムに対してインデックスを張る。

| カラム                                                        | インデックス種別                            | 理由                                           |
| ------------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------- |
| status                                                        | B-tree                                      | 公開中車両の絞り込みで常に使われる             |
| manufacturer_id, model_id, series_id, generation_id, grade_id | B-tree（各カラム）                          | 階層検索・絞り込み                             |
| price                                                         | B-tree                                      | 価格帯での絞り込み・並び替え                   |
| model_year                                                    | B-tree                                      | 年式での絞り込み・並び替え                     |
| mileage_km                                                    | B-tree                                      | 走行距離での絞り込み                           |
| deleted_at                                                    | Partial Index（`WHERE deleted_at IS NULL`） | 論理削除された車両を検索対象から高速に除外する |
| display_order                                                 | B-tree                                      | 管理画面の一覧並び替え表示用                   |

**補足**：内装色・外装色・シート素材・駆動方式・ミッション等の文字列系絞り込み項目は、在庫台数の規模（10〜50台）を踏まえるとインデックスの効果が限定的なため、初期リリースでは付与を見送り、将来的にパフォーマンス上の問題が確認された場合に追加する（BR-SCOPE-003：推測での過剰実装をしない）。

### 4.2 vehicle_photos / vehicle_videos / price_histories

| カラム     | インデックス種別 | 理由                               |
| ---------- | ---------------- | ---------------------------------- |
| vehicle_id | B-tree           | 車両詳細ページ表示時の子データ取得 |

### 4.3 articles（ブログ）

| カラム       | インデックス種別 | 理由                    |
| ------------ | ---------------- | ----------------------- |
| status       | B-tree           | 公開記事のみの一覧表示  |
| slug         | UNIQUE（自動）   | 記事詳細ページのURL解決 |
| published_at | B-tree           | 新着順表示              |
| deleted_at   | Partial Index    |                         |

### 4.4 encyclopedia_entries / timeline_events / library_entries

| カラム                            | インデックス種別 | 理由                |
| --------------------------------- | ---------------- | ------------------- |
| category                          | B-tree           | カテゴリ別絞り込み  |
| slug                              | UNIQUE（自動）   | 詳細ページのURL解決 |
| event_date（timeline_eventsのみ） | B-tree           | 時系列表示          |
| deleted_at                        | Partial Index    |                     |

### 4.5 seo_metas / related_contents / taggings（ポリモーフィック関連）

| カラム                                  | インデックス種別                     | 理由                                                              |
| --------------------------------------- | ------------------------------------ | ----------------------------------------------------------------- |
| (target_type, target_id)                | 複合インデックス                     | ポリモーフィック関連の検索は常にこの2カラムのセットで行われるため |
| (from_type, from_id) / (to_type, to_id) | 複合インデックス（related_contents） | 同上                                                              |
| (taggable_type, taggable_id)            | 複合インデックス（taggings）         | 同上                                                              |

### 4.6 customers / inquiries

| カラム                       | インデックス種別 | 理由                               |
| ---------------------------- | ---------------- | ---------------------------------- |
| customer_id（inquiries）     | B-tree           | 顧客タイムライン表示（FR-CRM-002） |
| response_status（inquiries） | B-tree           | 管理画面での未対応フィルタ表示     |
| phone, email（customers）    | B-tree           | 既存顧客の検索・重複チェック       |

### 4.7 favorites

| カラム                   | インデックス種別       | 理由                                                           |
| ------------------------ | ---------------------- | -------------------------------------------------------------- |
| (vehicle_id, session_id) | UNIQUE複合インデックス | 重複登録防止と同時に、人気ランキング集計（FR-FAV-004）の高速化 |

### 4.8 redirects

| カラム   | インデックス種別 | 理由                                                      |
| -------- | ---------------- | --------------------------------------------------------- |
| old_path | UNIQUE（自動）   | 旧URLアクセス時に高速にリダイレクト先を解決する必要がある |

## 5. 将来の見直し方針

- 在庫台数がアーカイブ含め数百台規模まで増加した際、実際のクエリパフォーマンスを計測した上でインデックスの追加・見直しを行う
- Supabase（PostgreSQL）の`EXPLAIN ANALYZE`等で実測してから最適化する。推測でのインデックス追加は行わない（BR-SCOPE-003）

## 6. Acceptance Criteria（本ドキュメントの受け入れ基準）

- [ ] FR-SRCH-001の全検索条件カラムについて、インデックス方針（付与する／規模的に見送る）が明記されている
- [ ] 論理削除（deleted_at）を持つ全テーブルについて、Partial Indexの方針が定義されている
- [ ] ポリモーフィック関連（seo_metas, related_contents, taggings）の複合インデックスが定義されている
- [ ] 想定規模（03_non_functional_requirements.md 3章）に対して過剰最適化になっていない
