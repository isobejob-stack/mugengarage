# pagination.md — ページネーション仕様

## 1. Purpose（目的）

車両一覧・検索結果・記事一覧・お問い合わせ一覧等、複数件を返すAPIエンドポイントにおけるページネーション（ページ分割）方式を統一する。

## 2. Scope（対象範囲）

rest_api.mdで定義する一覧系エンドポイント（GET系、複数件返却）すべてを対象とする。

## 3. 方式：オフセットベースページネーション

本プロジェクトの想定規模（在庫10〜50台、記事・図鑑等も同規模感）では、複雑なカーソルベースページネーションは過剰設計と判断し、シンプルなオフセットベース（`page` + `per_page`）を採用する（BR-SCOPE-003：推測での過剰実装をしない）。

### リクエストパラメータ

| パラメータ | 型      | デフォルト | 説明                           |
| ---------- | ------- | ---------- | ------------------------------ |
| `page`     | integer | 1          | 取得するページ番号（1始まり）  |
| `per_page` | integer | 20         | 1ページあたりの件数（上限100） |

例：`GET /api/vehicles?page=2&per_page=20`

### レスポンス形式

```json
{
  "data": [/* 車両オブジェクトの配列 */],
  "pagination": {
    "page": 2,
    "per_page": 20,
    "total_count": 47,
    "total_pages": 3
  }
}
```

## 4. 一覧系エンドポイントごとのデフォルト件数

| 対象                       | per_page デフォルト | 備考                                                                |
| -------------------------- | ------------------- | ------------------------------------------------------------------- |
| 車両一覧・検索結果（公開） | 20                  | スマホでのスクロール量を考慮                                        |
| 車両一覧（管理画面）       | 50                  | 管理者は一覧性を優先                                                |
| ブログ記事一覧             | 10                  |                                                                     |
| 図鑑・年表・ライブラリ一覧 | 30                  | 情報量重視（01_business_requirements.md 6章、車選びドットコム参考） |
| 整備実績一覧               | 20                  |                                                                     |
| オーナーズアーカイブ一覧   | 20                  |                                                                     |
| 顧客一覧（管理画面）       | 50                  |                                                                     |
| 問い合わせ一覧（管理画面） | 30                  |                                                                     |

## 5. 管理画面の並び替え（display_order）との関係

- `vehicles.display_order` 等、手動並び替え可能な一覧（FR-INV-008）では、ページネーションと`display_order`昇順ソートを併用する
- ドラッグ&ドロップ並び替え操作時は、対象ページ内の`display_order`のみを再計算し、全件の再計算は行わない（パフォーマンス配慮）

## 6. 将来の見直し方針

- 将来的にオーナーズアーカイブ等が数百件規模まで蓄積された場合でも、オフセットベースのページネーションは実用上問題ない規模と判断する（03_non_functional_requirements.md 3章の想定規模内）
- 万一、大量データによる性能劣化が実測された場合は、該当エンドポイントのみカーソルベースへの切り替えを検討する（推測での先行実装は行わない）

## 7. Acceptance Criteria（本ドキュメントの受け入れ基準）

- [ ] 全一覧系エンドポイントのページネーション方式が統一されている
- [ ] レスポンス形式に`total_count`・`total_pages`が含まれ、フロントエンド側でページ送りUIを実装できる情報が揃っている
- [ ] エンドポイントごとのデフォルト件数が、UI要件（01_business_requirements.md 6章）と矛盾しない
