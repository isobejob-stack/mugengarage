# 05_glossary.md — 用語集

## 1. Purpose（目的）

プロジェクト関係者（発注者・Claude・Claude Code）の間で用語の解釈がズレることを防ぐため、本プロジェクトで使用する主要な用語を定義する。特に「車両の階層構造」を表す用語（メーカー〜グレード）は、DB設計で階層テーブルとして扱うため、ここでの定義を厳密な基準とする。

## 2. Scope（対象範囲）

要件定義・DB設計・画面設計・API設計の全工程で共通して使用する用語を対象とする。

---

## 3. 車両階層に関する用語

本プラットフォームでは、車両を以下の階層で分類する（上位から下位の順）。

| 用語                     | 定義                                         | 例                                                                  |
| ------------------------ | -------------------------------------------- | ------------------------------------------------------------------- |
| メーカー（Manufacturer） | 自動車メーカー                               | Jaguar                                                              |
| 車種（Model）            | メーカーが展開する車種ライン                 | Eタイプ、XJ、XK                                                     |
| シリーズ（Series）       | 同一車種内のモデルチェンジ単位               | Eタイプ Series 1 / 2 / 3                                            |
| 世代（Generation）       | シリーズ内でのマイナーチェンジ・仕様変更単位 | 前期型／後期型 等                                                   |
| グレード（Grade）        | 世代内でのエンジン・装備差による仕様区分     | 4.2 FHC、3.8 OTS 等。グレード別テンプレート（FR-VEH-004）の適用単位 |

**注**：この階層は将来的に車種によって階層の深さが異なる可能性がある（例：シリーズが存在しない車種）ため、DB設計上は「必須ではない階層」として扱う（詳細はdatabase/で定義）。

## 4. 公開ステータスに関する用語

| 用語                          | 定義                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 公開（Published）             | 一般ユーザーが閲覧可能な状態                                                           |
| 非公開（Draft/Unpublished）   | 管理画面のみで閲覧可能、一般には非公開の状態                                           |
| 売約済（Sold）                | 販売が成立し、在庫としては非公開になるが、オーナーズアーカイブとして保持される状態     |
| 商談中（Negotiating）         | 購入検討・商談が進行中であることを示す、公開はされているが在庫状況を示す補助ステータス |
| Coming Soon                   | 今後入荷・公開予定であることを事前告知する状態                                         |
| 公開予約（Scheduled Publish） | 指定日時に自動的に「公開」ステータスへ切り替わる予約設定                               |

## 5. ドメイン・機能に関する用語

| 用語                                   | 定義                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Inventory（在庫管理）                  | 販売中・販売予定の車両を管理するドメイン                                                                       |
| Vehicle（車両）                        | Inventoryドメインが管理する個別の車両データ実体。車両情報の唯一の保持者（BR-DATA-002）                         |
| Knowledge系ドメイン                    | Vehicleに依存せず独立して存在する情報資産群。図鑑・年表・ライブラリを指す                                      |
| Jaguar図鑑（Encyclopedia）             | ブランド／シリーズ／車種／世代／エンジン／技術／歴史／用語集を図鑑形式で体系化したコンテンツ                   |
| Jaguar年表（Timeline）                 | ブランドの歴史・モデル登場・エンジン登場等を時系列で示すコンテンツ。特定車両には紐付けない                     |
| ライブラリ（Library）                  | Jaguarに関する知識を辞典形式で体系化したコンテンツ                                                             |
| 整備実績（Maintenance Records）        | 実際に行った修理・レストア・整備の記録。費用・ポイント・故障事例を含む                                         |
| オーナーズアーカイブ（Owners Archive） | 「売約済」になった車両の記録（写真・レストア履歴・販売履歴等）をサイト資産として保持し続ける仕組み             |
| CRM                                    | 顧客（見込み客含む）の情報・問い合わせ・購入/整備/売却履歴・お気に入り・メモ・リマインダーを一元管理する仕組み |
| 問い合わせ（Inquiry）                  | LINE／電話／メール／フォーム経由で発生した、顧客からの相談・連絡の記録                                         |

## 6. データ・設計に関する用語

| 用語                                 | 定義                                                                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 論理削除（Soft Delete）              | データを物理的に削除せず、削除フラグ等で「表示しない」状態にする方式。本プロジェクトでは物理削除を原則禁止する（BR-DEL-001） |
| SSOT（Single Source of Truth）       | あるデータについて、システム内で「正」となる保持場所を一箇所に限定する原則                                                   |
| Slug                                 | URLの一部として使われる、意味のある文字列識別子（例：`/vehicles/e-type-series1-42`）                                         |
| 301リダイレクト                      | 恒久的なURL変更を検索エンジン・ユーザーに伝えるHTTPリダイレクト。SEO評価の引き継ぎに必須                                     |
| Canonical（正規URL）                 | 重複コンテンツが存在する場合に、検索エンジンへ「正」のURLを伝えるためのメタ情報                                              |
| 構造化データ（Schema.org / JSON-LD） | 検索エンジンがページ内容を理解しやすくするための、決められた形式のメタデータ                                                 |
| OGP（Open Graph Protocol）           | SNSでシェアされた際のタイトル・画像・説明文等を制御するメタ情報                                                              |
| 監査ログ（Audit Log）                | 管理画面上での変更操作（誰が・いつ・何を変更したか）を記録したログ                                                           |
| ADR（Architecture Decision Record）  | アーキテクチャ上の重要な意思決定とその理由を記録するドキュメント。architecture/decisions/に格納                              |

## 7. 掲載情報に関する用語

中古車情報サイトで一般的に使われる語。表記を揺らさないため定義する（BR-DISP-002）。

| 用語 | 定義 |
| ---- | ---- |
| 車両本体価格 | 車両そのものの価格（税込）。諸費用を含まない |
| 支払総額 | 車両本体価格に諸費用を加えた、購入時に実際に支払う総額（税込）。購入検討者が最終的に比較する金額 |
| 諸費用 | 登録手続・納車準備・税金等の費用。支払総額と車両本体価格の差額にあたる |
| 車検整備付 | 納車時に車検を取得して引き渡す状態。現時点で有効な車検満了日は存在しない |
| 法定整備 | 納車前に行う法定点検整備。「整備付（費用込み）」「別途」「なし」を区別する |
| 修復歴 | 車体骨格部位の修復・交換の有無。事故歴とは異なる概念であり、購入判断で必ず確認される項目 |
| 記録簿 | 定期点検整備記録簿。旧車では整備履歴の有無が車両価値に直結する |
| ハンドル位置 | 右ハンドル／左ハンドル。輸入車では購入判断を大きく左右する |
