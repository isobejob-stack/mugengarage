# 04_business_rules.md — 業務ルール

## 1. Purpose（目的）

00〜03で定義した各ドキュメントに散在している業務ルールを一箇所に集約する。以降のDB設計・API設計・画面設計・実装は、必ず本ドキュメントのルールに矛盾していないかを照合すること。矛盾が生じた場合は、実装を進めず本ドキュメントを更新するか、ADR（decisions/）として例外理由を記録する。

## 2. Scope（対象範囲）

全ドメイン（Inventory / Vehicle / Search / Favorites / Blog / Encyclopedia / Timeline / Library / Maintenance / Owners Archive / CRM / Inquiry / LINE / SNS / SEO / Administration）に横断的に適用されるルールを対象とする。ドメイン固有の詳細ルール（例：車両ステータスの遷移条件の詳細）は、各ドメインの個別仕様書（今後作成）で定義する。

## 3. ルールID命名規則

`BR-[カテゴリ]-[連番]` とする。

| カテゴリ | 内容                       |
| -------- | -------------------------- |
| DATA     | データ整合性・重複管理禁止 |
| DEL      | 削除に関するルール         |
| DOM      | ドメイン独立性             |
| HIST     | 履歴・監査ログ             |
| URL      | URL・SEO永続性             |
| CONTENT  | コンテンツ入力ルール       |
| AI       | AI利用範囲                 |
| SCOPE    | スコープ・外部依存禁止     |
| DISP     | 公開サイトでの表示ルール   |
| FAIL     | 障害・通信失敗時の振る舞い |

---

## 4. データ整合性ルール（DATA）

| ID          | ルール                                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| BR-DATA-001 | 同じデータを複数のドメイン・テーブルで重複管理しない（Single Source of Truth）                                              |
| BR-DATA-002 | 車両情報（スペック・自由入力項目含む）はVehicleドメインのみが保持する。他ドメインは参照（紐付け）のみ行い、コピーを持たない |
| BR-DATA-003 | カテゴリ・タグ等の分類値はハードコードせず、管理画面から追加・編集可能なマスタデータとして管理する                          |

## 5. 削除ルール（DEL）

| ID         | ルール                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| BR-DEL-001 | すべての主要データ（車両・記事・図鑑・年表・ライブラリ・整備実績・顧客・問い合わせ等）は物理削除を行わず、論理削除（フラグ管理）とする                 |
| BR-DEL-002 | 論理削除されたデータは、公開ページ・検索結果・一覧には表示しないが、管理画面上では復元可能な状態で保持する                                             |
| BR-DEL-003 | 売約済み車両は削除しない。ステータスを「売約済」に変更し、オーナーズアーカイブとして保持し続ける（BR-DEL-001の特例ではなく、そもそも削除対象にしない） |

## 6. ドメイン独立性ルール（DOM）

| ID         | ルール                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| BR-DOM-001 | Knowledge系ドメイン（図鑑／年表／ライブラリ）は、Vehicle（在庫車両）の存在に依存せず、単体で作成・公開できる                      |
| BR-DOM-002 | Library（ライブラリ）は販売車両の有無に依存しない                                                                                 |
| BR-DOM-003 | Timeline（年表）はブランド資産として管理し、特定の車両インスタンスには紐付けない（図鑑項目等への紐付けは可）                      |
| BR-DOM-004 | Vehicle⇄Knowledge系ドメイン間の関連付けは、あくまで「紐付け（参照）」であり、片方の削除が他方のデータを道連れに削除してはならない |

## 7. 履歴・監査ルール（HIST）

| ID          | ルール                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| BR-HIST-001 | 車両価格の変更は、変更前価格・変更後価格・変更日時をすべて履歴として保持する（上書き禁止）                   |
| BR-HIST-002 | 管理画面上の主要な変更操作（誰が・いつ・何を・どう変更したか）は監査ログとして記録する                       |
| BR-HIST-003 | 価格履歴・監査ログは、通常のデータ削除操作の対象外とし、参照系データが論理削除されても履歴自体は保持し続ける |

## 8. URL・SEOルール（URL）

| ID         | ルール                                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-URL-001 | 公開URL（Slug）は永続化する。一度公開したURLは、意図しない変更・欠番を避ける                                                                       |
| BR-URL-002 | やむを得ずURL（Slug）を変更する場合は、必ず301リダイレクトを設定し、旧URLのSEO評価を維持する                                                       |
| BR-URL-003 | 全コンテンツタイプ（車両／記事／図鑑／年表／ライブラリ／整備実績）はSEOメタ情報（Title/Description/OGP/Canonical/Slug/構造化データ）を個別に持てる |

## 9. コンテンツ入力ルール（CONTENT）

| ID             | ルール                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| BR-CONTENT-001 | 自由入力項目（販売コメント・ストーリー等）はMarkdown形式で管理し、HTMLベタ書きは禁止する                     |
| BR-CONTENT-002 | グレード別テンプレートによる自動入力後も、管理者は内容を自由に編集できる（自動入力は初期値の提示にとどまる） |

## 10. AI利用ルール（AI）

| ID        | ルール                                                                                                                      |
| --------- | --------------------------------------------------------------------------------------------------------------------------- |
| BR-AI-001 | AI機能（文章生成・タグ提案・SEO提案・関連記事提案）はすべて「提案」にとどめ、確定・公開の最終判断は必ず人間（管理者）が行う |
| BR-AI-002 | AIによる自動公開・自動診断（車両状態診断等）は初期リリースで実装しない                                                      |

## 11. スコープ・外部依存禁止ルール（SCOPE）

| ID           | ルール                                                                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-SCOPE-001 | 外部媒体（グーネット・カーセンサー・車選びドットコム等）や外部APIに構造的に依存する設計を禁止する。連携は「将来追加可能な疎結合」として設計するにとどめる |
| BR-SCOPE-002 | LINEは初期リリースでは公式アカウントへの遷移導線のみとし、LINE API連携（自動応答等）は実装しない                                                          |
| BR-SCOPE-003 | 推測による仕様追加を禁止する。要件が不明確な場合は実装せず、Issue（tasks/）として記録し、人間の判断を仰ぐ                                                 |

## 12. 表示ルール（DISP）

2026-08-13 追加。実装時の判断が画面ごとにぶれ、表記揺れや誤解を招く表示が生じたため明文化する。

| ID | ルール |
| --- | --- |
| BR-DISP-001 | 未設定・未入力の項目は公開サイトに表示しない。空欄や「-」を並べると情報が無いことが強調され、かえって不信感につながるため |
| BR-DISP-002 | 同一項目の表示文言は1箇所に集約し、画面ごとに組み立てない（「車検残」「車検満了」「車検」のような表記揺れを防ぐ） |
| BR-DISP-003 | 購入判断に関わる情報を推測で補完しない。車検満了日が年月までしか判明していない場合、日を勝手に決めて表示してはならない |
| BR-DISP-004 | 価格は「支払総額」と「車両本体価格」を区別して扱う。絞り込み条件と一覧の表示が異なる基準を指してはならない |
| BR-DISP-005 | 遷移先が未設定の導線は表示しない。仮のURLや空リンクへ遷移させるより、導線自体を出さない方が利用者を裏切らない |

## 13. 障害時の振る舞いルール（FAIL）

2026-08-13 追加。屋外からの登録・モバイル回線からの送信が日常的に発生する運用であり、
通信失敗を通常起こりうる事象として扱う。

| ID | ルール |
| --- | --- |
| BR-FAIL-001 | 通信・保存に失敗した場合、必ず画面上の文言で利用者に伝える。無言で失敗してはならない |
| BR-FAIL-002 | 失敗時に送信中状態を解除し、操作不能のまま固まらないようにする |
| BR-FAIL-003 | 失敗時に利用者の入力内容を失わせない |
| BR-FAIL-004 | 楽観的に更新した表示は、保存失敗時に元へ戻す（記録されていないのに成功したように見せない） |
| BR-FAIL-005 | ページの主目的でない処理（サイトマップ生成・店舗情報取得等）の失敗により、ページ全体を停止させない |

## 14. Acceptance Criteria（本ドキュメントの受け入れ基準）

- [ ] 00〜03の各ドキュメントに記載された業務ルールが、漏れなく本ドキュメントに集約されている
- [ ] 各ルールがBR-IDで一意に参照可能になっている
- [ ] 以降のDB設計・API設計・画面設計のレビュー時に、本ドキュメントのルールとの矛盾チェックリストとして使用できる粒度である
